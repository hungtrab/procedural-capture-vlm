## 4. P2a — the teacher-forced refusal probe

### 4.1 The pre-sweep self-test, recorded before the sweep — and corrected

`next_step.md` requires it: "the P-format base `R` must be high on AdvBench and low on
Alpaca. Put that test in the report before the sweep." `probe.sbatch` runs it first and
**refuses to run the sweep if it fails**.

**The first run measured the wrong model, and both runs are kept.** Every adapter is loaded
by the time the self-test block runs, and `PeftModel` activates one of them by default, so
the first version — which did not wrap the call in `disable_adapter` — scored an *adapted*
model and labelled it `base`. It still showed the probe separating harmful from harmless,
which is what the self-test is for, but the figure was not the one asked for. Both are in
`outputs/scale/probe/`, the first as `p2a_<tag>_selftest_ADAPTED.json`.

| backbone | model | AdvBench mean `R` | Alpaca mean `R` | gap | |
|---|---|---|---|---|---|
| `q3vl8` | **base** (corrected) | **−2.1117** | **−19.0785** | **+16.9667** | pass |
| `q3vl8` | adapted (first run, mislabelled) | −0.3794 | −8.8592 | +8.4798 | pass |

The correction is confirmed independently: the sweep's own `base`/`P` cell over all 260 gray
rows is **−2.0842**, which matches the corrected −2.1117 over the first 100 and not the
−0.3794 of the first run. The first run's −0.3794 instead matches `af_s42`'s P value
(−0.3933) — i.e. exactly the adapter that was active.

`R = log Σ_s P(s)` over the four refusal starts, so base −2.11 is about 12% of the
probability mass on *beginning a refusal* on AdvBench against about 5e-9 on Alpaca. The probe
is measuring refusal. (n = 100 per side. The other two backbones' corrected self-tests are
folded in when their sweeps finish; their mislabelled first runs were `gm431` +9.6569 and
`q3vl32` +7.2980, both pass.)

### 4.2 The leading space

`next_step.md`: "Mis-tokenising it would compare out-of-distribution token sequences." A
refusal start is **never tokenised on its own**. `prompt+prefix` is tokenised, then
`prompt+prefix+start`, and the scored tokens are what the second has that the first does not.
That is only valid if the longer tokenisation *extends* the shorter, which BPE does not
guarantee across a merge boundary — so it is **asserted per row**, and a row that fails is
written `R=null` and counted in `BOUNDARY_MISMATCH` rather than scored on a guessed split.

## 4b. P2b — the chosen layers, written before any adapter was loaded

Phase 1 ran on `q3vl8` with **no adapter in memory at all**, so none could be the active one.
Fit set: **230 harmful** (AdvBench rows 260–519 minus the 30 `MIX_REQUESTS`) against **230
harmless** Alpaca rows absent from every `data_mix` file, in format P, 0 boundary failures.
Layers chosen on a fixed even/odd 50/50 split by held-out AUC:

    l_r* = 10   held-out AUC 1.0000      (refusal direction, post-instruction)
    l_h* = 13   held-out AUC 1.0000      (harmfulness probe, instruction-final)

written to `outputs/scale/probe/p2b_q3vl8_layers.json` before phase 2 was submitted; phase 2
aborts if that file is absent.

**The selection criterion is saturated, and that is a limitation worth stating.** AdvBench
against Alpaca is trivially separable for this model: **29 of 37 layers** reach AUC_r ≥
0.9999 and **19** reach AUC_h ≥ 0.9999. The argmax therefore picks the lowest-indexed member
of a large tie rather than a layer the data singled out. The tie-break is deterministic and
fixed in code, and the choice was made before any AF activation existed — so it cannot have
been tuned — but "chosen by held-out AUC" credits the criterion with more discrimination
than it has here. Per-layer AUCs for all 37 layers are in the same JSON.

`q3vl32` phase 1, same procedure: **`l_r*` = 17, `l_h*` = 21**, both AUC 1.0000, same
saturation.

most of the work of flattening the refusal signal — and the fine-tune is then what stops the
remaining signal from producing a refusal. P2c is the causal test of that reading.

## 5. Deviations

1. **`check_mixref.py` normalises one path prefix per side** before comparing the benign
   rows. Stated in 3.1 with the reason; it moves no row.
2. **The `xstest` cells do not re-run the benign gate.** Their adapters are byte copies of an

   `STEPS=158` applies one more optimiser update than 150. Keeping the 150 benign demos
   identical matters more. `countmix` made the same choice.

## 6. Incidents

**The demo-set build exits non-zero after fully succeeding.** Every file is written and
`os.replace`d and the success line prints, and then the interpreter dies in finalisation:

    Fatal Python error: PyGILState_Release: thread state ... must be current when releasing

the HF streaming datasets leave threads behind. `round4.sbatch` gated the cell on that exit
status, so `q3vl8` `mixref_p0`, `p8` and `t8` were all dropped as "BUILD FAILED" **with
complete, correct demo sets already on disk** — the three verified in 3.1. Cost: one job and
about twenty minutes. Fixed in `build_mixref.py` (`os._exit(0)`, skipping the finalisation
that crashes) and `round4b.sbatch`, where the keep/drop decision is made by `check_mixref.py`
reading the **files**, never by a process exit status. An incomplete build fails that check
anyway, so the artifact is the gate — which is what it should have been from the start. A new
file rather than an edit, because `round4.sbatch` was running at the time.

**Moved to `a100_genai_shared` at 19:40 UTC** at the owner's request. Slurm will not change a
running job's QoS, so the six jobs were cancelled and resubmitted. Nothing was lost: every
stage resumes by row count, the adapters already carried `SAVE_OK` so training was skipped on
restart, and a sweep for half-written final lines over every `res_*.jsonl` and probe file
found **0** to trim.
